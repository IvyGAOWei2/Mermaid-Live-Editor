# 技术方案

状态：v0.1 设计基线；最终实现与检查结果以 [progress.md](progress.md) 为准。

## 技术栈

采用 React 18 + TypeScript + Vite 6、Mermaid 11、CodeMirror 6。复用现成编辑器提供高亮、选区、撤销和重做；Mermaid 负责解析、布局与 SVG 渲染。选择兼容当前 Node 18 开发环境的工具版本，同时建议升级 Node 22，Vercel 使用 Node 22。锁定依赖文件随代码提交。

最终产物是静态文件 `dist/`，不需要后端、数据库、付费模型或运行时环境密钥。目标部署为 Vercel。

## 模块与数据流

- 应用界面：工具栏、双栏布局、状态提示、模板和帮助、大纲入口及覆盖确认。
- 编辑器：管理 CodeMirror 实例、变更通知、示例插入与撤销历史。
- 渲染与预览：去抖渲染、限制支持的图类型、错误信息、保留成功 SVG、缩放平移 / 适应窗口。
- 大纲转换：校验缩进、单根层级、空行与中文内容，输出带安全节点文字的 `mindmap`。
- 本地数据：载入 / 保存版本化草稿、覆盖前备份、异常提示。
- 文件：本地读取 `.mmd`，生成 UTF-8 源文件和独立 SVG 下载。

编辑器变更 → 更新当前代码 → 自动保存 → 去抖后 Mermaid 渲染 → 成功时替换预览 / 失败时只更新错误。保存独立于语法合法性，未完成或错误代码同样可保存。

## 渲染与安全

Mermaid 使用严格安全模式，图表内容不作为普通 HTML 执行。输入限制在 v0.1 支持范围；渲染结果通过请求序列或等效机制确保旧异步结果不会覆盖新输入。错误不清空最近成功图形，界面明确区分当前代码与上一次成功预览。SVG 导出应避免把旧图误当当前图。

所有依赖经构建打包，本地处理图表；不引入分析 SDK、外部 AI、图表上传或内容日志。图表不进入 URL、Git 或远程日志。浏览器存储不是加密保险箱，避免录入敏感资料；Mermaid 输入配置不能关闭应用安全边界。

## 保存与恢复

使用当前站点 origin 下的 `localStorage` 存储带版本号的代码草稿。刷新恢复当前浏览器最近成功写入的内容。写入失败（禁用存储、空间不足等）需要明确提示，仍允许导出 `.mmd`。

覆盖操作先确认，并保留可恢复的覆盖前代码；备份失败应有可见提示，不能误报已保护。多个电脑、浏览器、域名、localhost 与正式站点的存储相互独立，清理浏览器数据也会删除草稿。跨设备转移使用 `.mmd`。

## 发布与验证

本地执行 TypeScript 检查、相关单元测试和生产构建；浏览器验证中文、错误恢复、快速输入、刷新恢复、覆盖保护、缩放平移、文件往返和 SVG。CI 在 PR 与主分支运行检查，Vercel 从 GitHub 提交构建静态产物。预览部署用于验收，合并后正式发布。没有远程连接时仍完成本地代码和部署配置，并准确记录阻塞。
